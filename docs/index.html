The problem

MCP has no conformance test. A server can advertise any schema it likes, and a client cannot distinguish tool works from tool has never worked from tool is broken on my platform. Every one of those looks like success at the protocol level and failure at the value level, so an agent inherits the defect silently.

In the audit behind this page: 9 of 22 advertised tools were broken or degraded, while the server's own health check reported itself healthy. Three tools raised TypeError on every call. All findings were fixed upstream with regression tests — see the redacted sample report.

What you get

Tool health matrix

Every advertised tool called over stdio exactly as a client connects. Verdict per tool: works, broken, or platform-degraded.

Schema vs implementation

Static diff of advertised parameters against the signatures the dispatcher actually calls. Catches tools that have never worked.

Platform path drift

Paths and binaries validated against your real target OS — not the maintainer's distribution.

Dependency reality

Tools that shell out to binaries absent from minimal images, reported as "not found" while the binary works.

Credential exposure

Values fingerprinted by sha256 and hunted across git history, reflog, DBs, logs and archives. The value is never printed.

Fix pull requests

Optional. Fixes with regression tests written red first, so the defect is demonstrably reproducible and demonstrably gone.

How it runs

1.  You provide read-only access to the server (or a copy) and its intended environment
2.  We probe all tools over stdio / HTTP exactly as a client would
3.  Static cross-check of advertised schemas against handler signatures
4.  Filesystem paths and commands validated against the real target OS
5.  Credential fingerprint scan — values fingerprinted, never printed
6.  Report delivered, with a prioritized fix list and reproduction per finding
